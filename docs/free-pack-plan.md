# 免费卡包自动化计划

用户已确认方案 A：OpenCV 多尺度模板识别，使用提供的五张截图，集成现有工具。

## 流程与交互

- 在当前账号的卡包详情页启动；自动识别免费按钮、免费购买确认、开包动画和结果确认，随后切换右侧下一包。
- 付费卡包只切换下一包；购买动作必须同时匹配确认购买界面、免费文字和购买按钮，且此前已识别免费入口。
- 卡包 OCR 标题核验轮次，回到首包结束；限制扫描数与等待时间。短暂失焦恢复原窗口，窗口身份变化、识别异常和 F8/停止按钮中止。
- 新增独立 Fluent“免费开包”Page 与 ViewModel，经 DI 导航；界面显示阶段、已扫描数和已开包数。
- 运行与 Debug 日志记录阶段、匹配分数、动作和退出原因；诊断截图仅保存到系统 data 的有限数量目录。

## 实现阶段

1. OpenCV 原生依赖、嵌入模板、多尺度识别与截图回归；覆盖免费/付费区分、缩放、未知画面。
2. 可取消的开包状态机及 Windows 客户区捕获、前台核验和输入边界；通过隔离窗口验证真实 API。
3. 独立页面、进度/停止交互、DI/导航接入；现有单 STA 验证加入真实页面断言。
4. 使用说明、中文注释审计、全量 Core/App 行与分支 100% 覆盖、发布 EXE、交付包与 dev→master PR 更新。

每个已验收阶段由主代理单独 Git 提交；保留用户暂存的 .idea 文件。真实游戏验证使用当前账号免费卡包，结果单独记录；最终既有资源进程测试需游戏正常退出。

## 轮次误判、恢复与动画重试

1. OCR 读取独立卡包标题，规范化空白及标点后精确比较；完整回到首个标题才算一轮完成，其他历史重复单独记录。保留 200 包上限，新增超过 11 包与旧标识碰撞回归。
2. 用户已选择恢复方案 B：仅失焦、隐藏、最小化暂停；3 秒后主动恢复本轮原窗口，60 秒未恢复结束。进程或窗口身份、几何变化继续中止；进度和 F8 保留，恢复后重新捕获双帧，不重发已完成购买。
3. 观察等待由 250 毫秒缩短至 80 毫秒；明确免费、宝石费用否决、双帧和输入核验全部保留。
4. 仅本包免费购买成功且识别到开包锚点后授权原跳过位置，动画按钮暂未显示可节流点击；进入结果或详情后解除此授权。
5. 结果确认使用 200、400、800、1600、3200 毫秒后最多 5000 毫秒的指数间隔；每次重新核验双帧，最多 10 次且总等待 60 秒。返回原卡包详情后才计开包一次，免费购买动作仍只执行一次。
6. 状态机、视觉、系统边界分别补 RED 回归，由主代理统一运行、统计所有新增行与分支覆盖并打包。保留运行中的游戏、用户暂存文件和现有 Debug 实例。

## 结果确认的光标定位核验

最新生产日志中结果页连续识别成功，按指数间隔确认七次仍留在结果页。当前帧目标位于真实按钮内部，游戏与工具均以管理员权限运行；同权限单次输入诊断的 UAC 被用户取消，具体游戏阻断原因尚未完成现场验证。
