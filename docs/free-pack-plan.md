# 免费卡包自动化计划

用户已确认方案 A：OpenCV 多尺度模板识别，使用提供的五张截图，集成现有工具。

## 流程与交互

- 在当前账号的卡包详情页启动；自动识别免费按钮、免费购买确认、开包动画和结果确认，随后切换右侧下一包。
- 付费卡包只切换下一包；购买动作必须同时匹配确认购买界面、免费文字和购买按钮，且此前已识别免费入口。
- 卡包图像指纹去重，完成一轮结束；限制扫描数与等待时间。失焦、窗口变化、识别异常和 F8/停止按钮中止。
- 新增独立 Fluent“免费开包”Page 与 ViewModel，经 DI 导航；界面显示阶段、已扫描数和已开包数。
- 运行与 Debug 日志记录阶段、匹配分数、动作和退出原因；诊断截图仅保存到系统 data 的有限数量目录。

## 实现阶段

1. OpenCV 原生依赖、嵌入模板、多尺度识别与截图回归；覆盖免费/付费区分、缩放、未知画面。
2. 可取消的开包状态机及 Windows 客户区捕获、前台核验和输入边界；通过隔离窗口验证真实 API。
3. 独立页面、进度/停止交互、DI/导航接入；现有单 STA 验证加入真实页面断言。
4. 使用说明、中文注释审计、全量 Core/App 行与分支 100% 覆盖、发布 EXE、交付包与 dev→master PR 更新。

每个已验收阶段由主代理单独 Git 提交；保留用户暂存的 .idea 文件。真实游戏验证使用当前账号免费卡包，结果单独记录；最终既有资源进程测试需游戏正常退出。

## 现场启动与下一包故障回归

1. 核对系统日志：点击开始约20毫秒后首次客户区读取因窗口状态检查结束，扫描计数仍为0；先修复前台激活请求与实际前台生效之间的竞态。
2. 激活阶段有限等待实际游戏前台窗口；运行中的失焦、进程、位置和尺寸检查保持有效，并增加具体窗口状态诊断日志。
3. 使用新提供的已开包详情截图补付费识别与下一包箭头回归，验证没有点击付费购买入口；重新运行对应全部行与分支覆盖后提交和发布。

## 完整免费详情截图故障回归

1. 使用最新完整截图复现：日志显示详情已识别，但免费标志为 false；单按钮布局的免费文字低于原模板搜索区域。
2. 限定右下购买区域匹配“1包”和“1次免费”，核验两段文字的同一按钮位置；保留付费按钮、遮罩和费用确认的全部否定回归。
3. 用卡包标题区域标识同一卡包，验证同包插画变化仍保持身份，完成免费开包后继续下一包。
4. 检查鼠标按下与抬起是否跨越游戏输入帧；仅在可重复测试证明后修正发送时序。
5. 运行截图、状态机、窗口输入和页面回归，重新生成发布包。真实游戏验收在新版交付后进行。

## 费用 OCR 与宝石复核

用户已确认 Windows 内置 OCR 方案 A，本机已实测简体中文识别。

1. 捕获桌面中经过前台与几何核验的可见客户区，修复游戏窗口 DC 返回旧帧的问题。
2. 使用 Windows 简体中文 OCR 读取当前弹窗费用文字；明确识别“免费”才具备免费证据。
3. OpenCV 仅在弹窗费用区域识别宝石图标，OCR 同时拒绝消费、宝石费用与余额扣减证据；游戏右上角总余额不参与判定。
4. 原详情免费入口、弹窗标题、取消与购买按钮验证保留。缺少明确免费证据或存在费用证据时停止购买动作。
5. 真实免费与付费弹窗、长卡包名、缩放、OCR 失败和系统缺少语言模型分别回归，全部新增生产代码纳入行与分支覆盖。

## 边界

识别逻辑、运行状态机与 Windows 系统调用分别通过接口注入。状态机测试采用录制截图序列与输入记录；系统适配器通过隔离测试窗口验证，测试不切换真实账号或改动资源。全部自写生产代码纳入覆盖，不增加人工排除。
